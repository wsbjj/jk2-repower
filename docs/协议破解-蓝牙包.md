# JK-2 协议破解结果（已实测跑通）

> 来源：`jk-2蓝牙包.pklg`（iPhone SE / iOS 15.8.8 / BCM43452，PacketLogger 原始格式）
> 结论：**完整复电流程已还原，Mac 直连蓝牙即可复电，不需要手机、不需要扫码、不需要登录。**

---

## 一、pklg 文件格式（自己解析出来的）

PacketLogger 原始格式，记录结构：

```
[4 字节] 总长度（含时间戳，单位字节）
[8 字节] 时间戳（CFAbsoluteTime，小端）
[剩余]   数据（长度 = 总长度 - 8）
```

数据首字节表示类型：

| 首字节 | 含义 |
|---|---|
| `0x01` | HCI 命令 |
| `0x02` | ACL 数据（承载 L2CAP/ATT） |
| `0x04` | HCI 事件 |
| `0xfc` | 文本日志 |

这份包共 **201 条记录**，其中 24 个 ACL 包。捕获头信息：

```
Product: iPhone8,4          ← iPhone SE 一代
Software: Version 15.8.8 (Build 19H422)
Chipset: BCM_43452
```

## 二、真实 BLE 交互（重组后）

L2CAP 重组后得到 14 个 ATT PDU，关键序列：

```
#6  Write Request  handle=0x0009  len=2   02 00      ← 开通知(CCCD)
#9  Write Request  handle=0x001a  len=2   01 00      ← 开通知(CCCD)
#10 Write Request  handle=0x0019  len=80  D1:2026,17:11,29:15,91:11,80:22,
                                          D6:32,85:05,85:00,91:11,149:58,
                                          336:Y,247:N,D13:Y
#11 Write Request  handle=0x0019  len=80  {"rpcResponse":"6Njb1hvh967m5GIv1QEXMQ==:IrSbXEbi...
#12 Write Request  handle=0x0019  len=80  7Met4fniHoqypFTb1ib3wxSv6dKYMOhuNPM1swrcBn...
#13 Write Request  handle=0x0019  len=11  bblGHrTW+"}
```

**关键结论：**

1. **数据通道是 `0x0019`**（即 `0000ffe1` 的 value handle）
2. 写入用 **Write Request（带响应，opcode 0x12）**
3. **每段 80 字节**
4. 顺序：**先写明文配置串，再写加密 RPC**，缺一不可
5. 加密 RPC 就是云端 `getCurrentRPCStr_B03.08` 的返回，格式 `{"rpcResponse":"<IV_b64>:<密文_b64>"}`

之前我用明文配置串单独写，设备只回个版本号就完了 —— 因为**真正的指令是那串加密的**。

## 三、完整复电流程（已验证）

```python
# 1. 向云端要两条指令（设备令牌即可，无需登录）
cfg = POST /api/v1/B03-XXXX/rpc  {"method":"getCurrentRPCStr",       "params":{"temperature":"25"}}
enc = POST /api/v1/B03-XXXX/rpc  {"method":"getCurrentRPCStr_B03.08","params":{"temperature":"25"}}

# 2. 连蓝牙（设备名 B03-XXXX，服务 ffe0，特征 ffe1）
# 3. 写 cfg（分 80 字节段，Write Request）
# 4. 写 json.dumps(enc)（分 80 字节段，Write Request）
# 5. 设备回报状态
```

## 四、设备状态回报格式

```
1:B03-XXXX,2:20261115,3:112631,4:744.61,5:93.8,6:232.3,7:0.625,8:0.648,
9:0,10:0,11:0,12:0,13:2,14:0.3,15:0.266,16:0.004,17:1,
18:POWER02,19:B03.08,20:790,21:20261115,22:085448,23:0,
24:Y,25:N,26:Y,27:0500-1158,28:63,29:0,30:0
```

| 字段 | 含义 |
|---|---|
| 1 | 设备名 |
| 2 / 3 | 日期 YYYYMMDD / 时间 HHMMSS |
| 4 | 累计电量 kWh |
| 5 | （待定，疑似剩余/功率相关） |
| 6 | 电压 V |
| 7 | 电流 A |
| 8 | 功率因数 |
| 13~17 | 各类告警计数 / 参数 |
| 18 / 19 | 固件名 POWER02 / 版本 B03.08 |
| 21 / 22 | 上次事件日期 / 时间 |
| **24 / 25 / 26** | **三个开关 Y/N** |
| **27** | **供电时段，12 小时制**：`0500-1158` = 05:00 ~ 23:58 |
| 28 | 63（待定） |

注意 27 是 **12 小时制**：云端属性 `TimerOneOff=23:58`，设备里存的是 `1158`。
所以看到 `1158` 不要以为是上午 11:58。

## 五、现在能做什么

```bash
./run.sh jk-status           # 读状态
./run.sh jk-recover          # 复电
./run.sh jk-watch            # 常驻：检测到断电就自动复电
```

或者直接：

```bash
python3 ble/jk2.py status
python3 ble/jk2.py recover
python3 ble/jk2.py watch --interval 30
```

**换房间**：`--token B03-XXXX`（设备名即令牌）。

## 六、注意事项

1. **必须人在设备蓝牙范围内**（10 米内）。这就是为什么原方案没法"云端定时"——
   设备是纯 BLE，没有 WiFi/4G。
2. **Mac 要放在宿舍**，`jk-watch` 常驻即可实现全自动。
3. 蓝牙扫描找设备需要 8~10 秒（macOS 的随机私有地址每次变）。
   可以把 `jk2.py` 里的 `find_device` 改成记住上次的地址加速。
4. **别频繁打**。`watch` 默认 60 秒一轮，足够。设备是低功耗表计，别当玩具。
5. 加密 RPC 是云端实时生成的，每次都要重新取，不能缓存复用。
