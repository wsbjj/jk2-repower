# 网页版（单文件 HTML）

`jk2.html` —— 一个文件搞定，浏览器里直接连蓝牙、调云端、复电。
不用装 Python，不用开终端。

---

## 怎么打开

**双击 `打开网页版.command`**，会自动起本地服务并打开 Chrome。

或者手动：

```bash
cd ~/代码/pj
python3 -m http.server 8080
# 然后浏览器打开 http://localhost:8080/jk2.html
```

---

## ⚠️ 两个硬性要求

### 1. 必须用 Chrome 或 Edge

**Safari 不支持 Web Bluetooth**，打不开。

### 2. 必须走 `http://localhost`

直接双击 `jk2.html`（`file://` 协议）**不行** ——
Web Bluetooth 只在安全上下文下可用，`file://` 不算。

所以必须用那个 `.command` 启动，或者手动起个 `http.server`。

---

## 能做什么

| 功能 | 说明 |
|---|---|
| 添加设备 | 弹窗选 `B03-xxxx`，记住授权 |
| 查询状态 | 电压 / 电流 / 电量 / 时段 / 开关 |
| 复电 | 一次点击 |
| 守护模式 | 每 60 秒查一次，断电自动复电（页面要开着） |

---

## 它和 Python 版的区别

| | 网页版 HTML | Python 版 |
|---|---|---|
| 安装 | 零 | 要装 Python + bleak |
| 打开方式 | 双击 | 终端 / launchd |
| 多设备 | 每台要点一次选择框 | 配置好自动轮询 |
| 后台常驻 | ❌ 页面关了就停 | ✅ 开机自启 |
| 自动化 | 弱 | 强 |

**结论**：网页版适合**临时用、给别人用、在别的电脑上救急**。
要 7×24 全自动，还是 Python 版 + launchd。

## 技术要点（为什么能这么干）

### CORS 是通的

我实测过云端接口的预检：

```
access-control-allow-origin: http://localhost:8080
access-control-allow-methods: POST
access-control-allow-headers: content-type
```

服务器会回显 `Origin`，所以浏览器能直接 `fetch`。

### BLE 参数

```js
service 0000ffe0-0000-1000-8000-00805f9b34fb
char    0000ffe1-0000-1000-8000-00805f9b34fb
写入    writeValueWithResponse（= Write Request）
分片    每段 80 字节
```

和抓包还原的完全一致。

### 流程

```
1. fetch getCurrentRPCStr       → 明文配置串
2. fetch getCurrentRPCStr_B03.08 → 加密 RPC
3. 连 BLE，startNotifications
4. 写配置串（分片）
5. 写加密 RPC（分片）
6. 等 notify 里的状态回报（24:Y / 24:N）
```

### 设备授权复用

用 `navigator.bluetooth.getDevices()` 拿浏览器已记住的设备，
避免每次都弹选择框。Chrome 85+ 支持。

---

## 已知限制

1. **Safari / Firefox 用不了**（Firefox 根本没实现 Web Bluetooth）
2. **页面必须开着**才能守护，关掉就停
3. **每台设备第一次要手动点一次**选择框（浏览器安全限制，绕不过）
4. 电脑休眠时蓝牙会断，唤醒后需要重新点一次
